## Schema and migration decision, before implementation

New relation, return-contract, state and projection canonical shapes use
`/2.0`. Envelope intake remains `line.report-envelope/1.0`; accepted-envelope
and holding canonical shapes stay unchanged. Prior serialized bytes and seals
are historical evidence, never silently rehashed as if unchanged.

Historic `human_decision_ref` remains stored, but supplies no resolution
authority. Promotion writes a distinct `classification_decision_ref`.
Migration requires an explicit new registration and, for any claimed
resolution, a new decision event naming the exact target digest, evidence,
next use, and basis state. There is no automatic clearance migration.

The return-pair model is retained (the review explicitly permits this): every
immutable field must match one preceding open record. A partial completion
may have one explicitly linked remainder obligation; only its verified
closure closes the parent's remainder. Changing obligation terms is a new
obligation plus a targeted rescope, never an edited completion.

`raw_state` is the inspection/defect-fixture seal constructor. `genesis_state`
and `update_state` validate structure; projection also validates independently.
A seal certifies bytes, not valid bookkeeping. Typed structural errors carry
all issues and do not represent a substantive `-1` against the subject.

Decision events are append-only, exact-target and exact-use. Acknowledgment
is neutral; resolve/rescope cannot clear protected absence. Contradictory
clear/reopen decisions remain visible and hold; tuple order selects no winner.
Dates are real calendar dates. Backdated reviews are allowed: append sequence,
review date and externally declared anchoring date are distinct facts.

  `tests/test_review_regressions.py` cover every relation type, acknowledgment,
  scoped resolution, partial/remainder verification, two-return single-target
  rescope, conflicting clear/reopen events, protection and agreement inflation.
  The compatibility projection decision argument remains an inert stored
  receipt; authority must be appended to the state.
- WR-02: the permitted pair model avoids replacing historical records.
  Changed subject, rationale, alternatives, change condition, standing,
  protection, trigger, acceptance and prior-state reference all fail structure;
  orphans, reordered pairs and ambiguous duplicates also fail. Changing the
  contract ID creates an orphan, not a discharge.
- WR-03: malformed local states are rejected by public `project`; raw
  imports remain inspectable. Chain-only defects need chain context and are
  rejected by `project_chain`; a supplied foreign/fabricated projection needs
  `check_projection`. A state-only function cannot detect a different omitted
  chain or an unrelated projection object. This is the explicit adaptation of
  “every planted defect through projection,” preserving the distinct claim
  boundaries instead of pretending missing context was checked.
- WR-06/07/10: `tests/test_interchange_hardening.py` covers strict JSON,
  bounded depth/size, cycles, Unicode, caller mutation before/after sealing,

  the reviewed revision and the new implementation; unchanged envelope bytes
